## 구현 전략

전체를 여러 Phase로 나눈다. Phase가 끝날 때마다 테스트를 실행하고 사용자 확인 후 다음 Phase로
진행한다.

Phase 1~4(v1)·8~16(v3 재설계 및 후속 피드백 반영)는 전부 완료됐다. 각 Phase의 구현 내용·
검증 로그·시행착오는 `docs/history/PLAN_ARCHIVE.md`에 전문 그대로 보존돼 있다 — 코드 동작
방식은 `docs/SPEC.md`가 최신 기준이므로, 과거 Phase 로그는 "왜 지금 이렇게 됐는지" 배경이
필요할 때만 참고한다.

**2026-07-10에 세운 로드맵 초안(Phase 5~7)이 2026-08-15에 전부 완료되며, 지금까지 계획된
Phase는 모두 끝났다.** 2026-08-14 세션에서 범위가 훨씬 크게 확장되며 Phase 8~15로 대체
착수했고, 2026-08-15엔 실사용 피드백으로 Phase 16(공고 최종검수)에 이어 옛 로드맵의
Phase 5(안정성/신뢰성)·6(필터 고도화)·7(지원 상태 추적)까지 순서대로 마무리됐다. 새로운
개선 아이디어가 생기면 이 문서에 새 Phase로 추가해 이어간다.

## 완료 Phase 요약

| Phase | 내용 |
|---|---|
| 1~4 (v1) | 프로젝트 뼈대, 이중 소스 수집(사람인+원티드), 필터링, X 마커 |
| 8 | `fetch_jobs.py` 단일 스크립트 → `jobfind/` 패키지 재구조화 |
| 9 | HF 임베딩 기반 관련성 평가(직무x도메인 랭킹) |
| 10 | 수동 추가(`add`) + 자소서 선택 마커(`select`) |
| 11 | AI provider 추상화 계층 |
| 12 | 자소서 오케스트레이션 파이프라인(`write`) |
| 13 | 문서 정리(v3 재설계 반영) |
| 14 | 실사용 피드백 3건 반영(`.env` 통합, 관련성 결합식 수정, writer 작성거부 방지) |
| 15 | 관련성 모델 교체, DART 연동, planner 웹 검색 허용 |
| 16 | 공고 최종검수(`verify`) — 목록 요약과 실제 상세 요건(사람인 이미지/원티드 텍스트)을 AI로 대조 |
| 5 | 안정성/신뢰성 — 소스 요청 실패/사람인 페이지 상한 감지, `output/run_log.txt` 누적 기록 |
| 6 | 필터 고도화 — career_type 다중선택, 회사 블랙리스트, 마감임박 D-day 표시 (exp_range는 overlap 유지 확정) |
| 7 | 지원 상태 추적 — `[상태]` 마커 신설(지원함/면접/합격 등 집계), "탈락"은 `[X]`처럼 제거 + `archived_ids.txt` 기록 |

> 각 행의 상세 구현 목록·검증 방법·실측 결과는 `docs/history/PLAN_ARCHIVE.md`의 동일 Phase
> 번호 섹션 참고.
