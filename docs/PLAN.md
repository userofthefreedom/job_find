## 구현 전략

전체를 여러 Phase로 나눈다. Phase가 끝날 때마다 테스트를 실행하고 사용자 확인 후 다음 Phase로
진행한다.

Phase 1~4(v1)·8~16(v3 재설계 및 후속 피드백 반영)는 전부 완료됐다. 각 Phase의 구현 내용·
검증 로그·시행착오는 `docs/history/PLAN_ARCHIVE.md`에 전문 그대로 보존돼 있다 — 코드 동작
방식은 `docs/SPEC.md`가 최신 기준이므로, 과거 Phase 로그는 "왜 지금 이렇게 됐는지" 배경이
필요할 때만 참고한다.

**2026-07-10에 세운 로드맵 초안(Phase 5~7)이 2026-08-15에 전부 완료되며, 당시까지 계획된
Phase는 모두 끝났다.** 2026-08-14 세션에서 범위가 훨씬 크게 확장되며 Phase 8~15로 대체
착수했고, 2026-08-15엔 실사용 피드백으로 Phase 16(공고 최종검수)에 이어 옛 로드맵의
Phase 5(안정성/신뢰성)·6(필터 고도화)·7(지원 상태 추적)까지 순서대로 마무리됐다.

2026-08-15엔 `write`를 실제로 실행해 나온 산출물(`output/cover_letters/`)을 분석한 결과
발견된 문제들을 Phase 17~18로 착수했다 — 초안 재작성 루프 부재로 인한 약점 반복 노출(17),

### Phase 22 검증 기록

실사용 중 나온 불편 3건을 다뤘다.

**(1) notes.md 자동 생성**: `selection.sync_materials_folders()`가 `materials/` 폴더 생성
직후 `notes.md`가 없을 때만 빈 템플릿(자소설닷컴 등에서 확인한 실제 문항을 옮겨 적으라는
안내 포함)을 만든다. 이미 있으면 건드리지 않아 사용자가 채운 내용은 안전하다.

**(2) 폴더명 사람이 읽기 쉽게 변경**: `storage.cover_letter_folder_name(job_id, block)`을
새로 만들어 `<ID>_<회사명>_<직무명>` 형식을 계산하고, `selection.py`(materials/ 준비)와
`pipeline/orchestrator.py`(plan/draft 등 저장)가 동일 함수로 같은 폴더명을 쓰도록 통일했다.
`[회사]`/`[제목]`이 없는 블록(테스트 등)은 ID만 반환해 기존 동작과 호환되므로, 이 부분을
검증하던 기존 orchestrator 테스트 11개는 수정 없이 그대로 통과했다 — 회사/제목 필드가 있는
블록을 쓰는 selection 테스트 2개만 새 폴더명에 맞춰 수정했다.

**(3) 자소설닷컴 연동 검토 후 보류**: 사용자가 "사람인·원티드는 실제 자소서 문항이 거의
없고 자소설닷컴엔 있다"고 문제 제기해 `collect`의 세 번째 소스로 추가하는 안을 검토했다.
Claude in Chrome으로 실제 접속해 확인한 결과 (a) 이용약관 제14조가 자동화 수집을 명시
금지하고 있었고 (b) 공고 데이터가 원티드처럼 공개 JSON이 아니라 로그인 세션이 필요한
비공개 API였다(페이지 내부 데이터를 읽으려 하자 확장이 "쿠키/세션 정보 포함"으로 자동
차단함 — 개인 계정 세션을 코드에 심어야 하는 구조라는 뜻). 사용자에게 두 사실을 모두
알리고 확인했고, 최종적으로 자동 수집은 보류하고 (1)의 notes.md 템플릿에 안내를 강화하는
쪽으로 대체하기로 했다. 상세 근거는 `docs/SPEC.md` §13-4a 참고.

**(3) 이후 같은 세션에서 뒤집힘 → Phase 23 참고.** 사용자가 "나는 지금 로그아웃 상태에서도
자소설닷컴을 정상적으로 쓰고 있다"고 반박해 재검증한 결과, 위 (b) 판단이 틀렸음이
드러났다.

테스트 6개 추가(`tests/test_storage.py` 4개 — `cover_letter_folder_name` 케이스,
`tests/test_selection.py` 2개 — notes.md 자동 생성/미덮어쓰기), 기존 2개 수정(폴더명 변경
반영), 전체 스위트 236→242개 전부 통과.

### Phase 23 검증 기록

Phase 22 (3)의 "보류" 판단을 같은 세션에서 뒤집은 경과와 최종 구현이다.

**재검증**: 로그아웃 탭에서 `/recruit`를 다시 열어 확인하니 우측 상단에 "회원가입/로그인"
버튼이 떠 있는 상태에서도 회사 목록이 정상 표시됐다. Phase 22에서 "쿠키/세션 정보 포함"
차단을 근거로 로그인 세션이 필요하다고 판단했던 건, 익명 방문자에게도 발급되는 애널리틱스
클라이언트 ID(`userId=...`)를 로그인 계정으로 잘못 해석한 것이었다. `fetch(url,
{credentials:'omit'})`으로 쿠키 없이 직접 호출해 `POST /employment/calendar_list.json`과
`GET /api/v1/employment_companies/<id>?skip_read_log=true` 둘 다 200을 반환함을 확인했다
— 원티드와 마찬가지로 인증 불필요한 공개 API였다. 이용약관 제14조의 명시적 자동화 수집
금지는 로그인 여부와 무관하므로 이 사실은 그대로 다시 알렸고, 사용자가 리스크를 감수하고
진행하기로 확정했다.

**설계 문제와 해결**: 목록 API(`calendar_list.json`)엔 직무명이 없다 — 회사 전체를 아우르는
제목만 있고, 실제 직무별 명칭(`employments[].field`)은 회사마다 상세 API를 따로 불러야
얻을 수 있다. 사용자가 "회사명만으로는 직무 관련성을 전혀 판단할 수 없으니, 상세조회 없이
수집하는 건 의미가 없다"고 지적했다 — 맞는 지적이라 처음 제안했던 "회사명으로 1차
필터링" 안을 폐기했다. 그런데 한 달에 회사가 400곳 넘게 열려있어(실측 463건) 매일 전체를
상세조회하면 사람인·원티드보다 요청량이 커지는 문제가 남았다. 해결책은 기존 `collect`
흐름이 이미 쓰고 있던 `skip_ids`(활성+탈락+보관 ID) 패턴을 재사용하는 것 — 목록은 매일
가볍게 전체를 받되, **`jobs_all.txt`에 이미 있는 회사는 상세조회를 건너뛰고 신규 회사만
상세조회**한다(`fetch_jasoseol_all(skip_ids)`). 최초 도입 시점만 그 달 전체가 "신규"라
상세조회가 크게 발생하는 일회성 비용이 있다는 점을 사용자에게 알리고 동의를 받았다.

**실제 API e2e 검증** (2026-08-17, 모킹 없이 실제 엔드포인트 호출):
- `fetch_jasoseol_all(set())` — 오늘~30일 범위 201개 회사, 18초 소요(0.09초/회사), 그중
  26개 회사에 자소서 고정질문 직무가 있었다.
- 사용자의 실제 `.env` 필터(`FILTER_KEYWORDS`: 서비스기획/PM/PO 등, `FILTER_LOCATIONS`:
  서울/경기 등)를 그대로 적용한 `filter_jobs()` 결과 201건 → 6건. 살아남은 블록에
  `[직무] PM`처럼 직무 키워드가 정상적으로 반영됨을 확인했고, 근무지 필드가 없는데도
  `FILTER_LOCATIONS`에 걸러지지 않고 통과함을 확인했다(§`filter_location`의 소스 예외
  처리가 의도대로 동작).
- 이 테스트는 실제 파일을 건드리지 않고 콘솔 출력만 확인했다 — `output/jobs_all.txt`는
  그대로 보존됨.

**주의**: `filter_career_type`의 기존 테스트(`test_filter_career_type_both_rejects_blank`)
는 "일반 소스가 experience 필드를 비워두면 거부한다"는 의도된 동작이라, 자소설닷컴처럼
필드 자체가 없는 소스와는 원칙이 다르다. 소스 전체를 permissive하게 바꾸는 대신
`job["source"] == "자소설닷컴"`일 때만 필터를 우회하도록 좁혀서, 기존 테스트/의도를
건드리지 않았다.

테스트 20개 추가(`tests/test_jasoseol.py` 13개, `tests/test_dedup.py` 3개,
`tests/test_filters.py` 2개, `tests/test_storage.py` 2개), 기존 테스트 다수 수정
(`fetch_all()`이 `skip_ids` 인자를 받고 5-튜플을 반환하도록 시그니처가 바뀌어
`test_dedup.py`/`test_collect.py`의 호출부 전부 갱신), 전체 스위트 242→266개 전부 통과.
